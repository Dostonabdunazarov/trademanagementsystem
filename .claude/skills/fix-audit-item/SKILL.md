# /fix-audit-item <ID…>

1. Найти пункт в `AUDIT_2026-09-29.md` и **перепроверить по текущему коду**: номера строк могли уехать, пункт мог быть уже исправлен. Если уже исправлен — сказать об этом и остановиться.
2. Если исправление меняет поведение, заметное пользователю (права ролей, запрет действия, формулу отчёта), или требует миграции с изменением данных, сначала коротко описать план и **спросить подтверждение**. Примеры: SEC-4 «кассир не может отменять», BIZ-3 или BIZ-4 «прибыль пересчитается».
3. Исправлять минимально, в стиле окружающего кода. Правила в `.claude/rules/` действуют.
4. Написать тест, который падал бы без исправления:
   - бэкенд — интеграционный тест;
   - фронтенд — vitest.
5. `/verify`. Для изменений в документах и отчётах — ревью субагентом `ledger-logic-reviewer`, для API — `tenant-security-reviewer`.
6. В `AUDIT_2026-09-29.md` пометить пункт `✅ исправлено (YYYY-MM-DD)` и одной строкой написать, что сделано. Не удалять пункт.
7. Коммит — только если пользователь просил. Сообщение: `fix(<scope>): <что> (AUDIT <ID>)`. **Не пушить**: push в `main` = деплой.
