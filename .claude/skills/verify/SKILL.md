# /verify — проверки TradeMS

Аргумент (необязательный): `backend`, `frontend` или `all` (по умолчанию). Если аргумента нет, выбрать по `git status`: какие части затронуты, те и проверять. Если непонятно — проверять всё.

## Бэкенд (из `TradeMS/`)

1. `dotnet build TradeMS.slnx -nologo -v q`. Новые предупреждения `CS*` в изменённых файлах считаются проблемой. `NU190x` (уязвимые пакеты) упомянуть отдельно.
2. Если менялись сущности или `AppDbContext`: `dotnet ef migrations has-pending-model-changes -p TradeMS.Infrastructure -s TradeMS.Api`. Pending-изменения = забыта миграция.
3. `dotnet test TradeMS.slnx --no-build` — если доступен Docker (`docker info`) **или** задан `TRADEMS_TEST_DB` (пустая тестовая БД, см. docs/development.md#тесты). Иначе не запускать и в отчёте написать: «интеграционные тесты не запускались: нет Docker/тестовой БД».

## Фронтенд (из `trade-ms-ui/`)

1. `npx tsc -b`
2. `npm run lint` — должно быть 0 ошибок.
3. `npx vitest run` — все тесты зелёные.
4. Если менялся `package.json`: `npm audit --omit=dev`.

## Отчёт

Короткая таблица: проверка → ✅ / ❌ / ⏭ (не запускалась и почему). При ❌ привести ключевые строки вывода. Не писать «всё работает», если что-то не запускалось.
