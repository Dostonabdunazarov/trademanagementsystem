# /tenant-audit

Аргумент: область (`Documents`, `Reports` …), путь к файлу или `diff` (по умолчанию — изменения относительно `origin/main`).

## Как проверять

Для каждого эндпоинта в области составить строку таблицы и проверить по коду эндпоинта **и** его handler:

| Маршрут | Роль | CompanyId | BranchId для не-Admin | Внешние id проверены | pageSize ограничен |

Критерии:
1. **CompanyId** берётся из claim и применяется к **каждой** выборке в handler, включая `Include`-навигации, через которые меняются данные (например, `doc.Counterparty.Balance`).
2. **Внешние id из тела** (`CounterpartyId`, `ProductId`, `AccountId`, `BranchId`, `CurrencyId`, `GroupId`) проверяются: `CompanyId`, `DeletedAt == null`, активность, а для кассы — филиал.
3. **Не-Admin:** `branch_id` из токена перекрывает параметр запроса. Действует и на чтение: список, get-by-id, отчёты, кассы. Если `branch_id` отсутствует, ответ 403, а не «всё».
4. **Роль:** что должен уметь Cashier, Manager, Admin. Админские операции: пользователи, филиалы, валюты, курсы, кассы, удаление и, скорее всего, отмена проведённых документов.
5. **Последовательные id** (`Document.Id` — `long`) перебираются, поэтому get-by-id обязан проверять и компанию, и филиал.
6. **Сессии:** смена роли, `IsActive` или пароля должна отзывать refresh-токен.

## Отчёт
Таблица выше. Затем список находок: серьёзность, `file:line`, сценарий эксплуатации, исправление. Известные находки из `AUDIT_2026-09-29.md` помечать их ID (SEC-1…SEC-8) и не выдавать за новые.
